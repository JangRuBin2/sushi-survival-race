## 1. 진단 — 지금 "통과" 순간이 얼마나 밋밋한가 (코드 근거)

탈락은 핵심 콘텐츠로 설계돼 3초짜리 멀티 비트 연출(카메라·도장·말풍선·효과음, `EliminationCutsceneLogic`)을 받는데, **통과는 그 반대쪽 끝에 있다.**

- `src/client/ui/HudController.luau:21` `personalResultText`가 통과 시 보여주는 전부: `✅ {place}번째로 통과했어요!` 한 줄 텍스트, **본인 화면에만**.
- `src/client/Sfx.luau:461` — 통과 시 재생하는 것도 `Sfx.play("Qualified")` **효과음 하나**뿐, 그것도 본인에게만(`result.userId == player.UserId`).
- `src/server/RoundService.luau:305-311` — 서버가 통과를 처리하는 전체 코드:
  ```lua
  EliminationService.passed(roomId, player, place)
  if inGame then
      CharacterUtil.toLobby(player)
  end
  ```
  **판정과 이동(코스 밖 대기석 텔레포트)이 같은 틱에 끝난다.** 캐릭터가 결승선 근처에서 멈추거나 포즈를 취할 시간이 전혀 없다 — 통과하는 순간 화면에서 사라져 로비 스폰(`LobbySpawn`, `CharacterUtil.toLobby`)에 다시 나타난다.
- **다른 플레이어는 누가 통과했는지 월드에서 전혀 볼 수 없다.** `broadcast`가 `PlayerResult`를 그 방 전원에게 보내긴 하지만, 그걸 듣는 클라이언트 쪽 월드 연출은 탈락(`EliminationCutsceneController`)에만 있고 통과용은 없다. 통과는 순전히 "HUD 텍스트 + 본인 효과음"이다.

**결론**: 탈락은 "먹혀도 웃겨서 억울하지 않다"(GDD 1.1 차별점)를 노리고 공들였는데, 통과는 그 대칭점이 없어서 "이겨도 아무 느낌이 없다"는 비대칭이 생긴다. 사용자가 요청한 "통과자 세레모니"는 이 비대칭을 메우는 작업이다.

## 2. 기술 기반 확인 — 이모트는 어떤 형태로만 가능한가

`src/shared/SushiBody.luau`를 보면 초밥 캐릭터는 Roblox 표준 R15 아바타가 아니다(GDD 6 "로블록스 아바타 옷·체형은 불러오지 않아요"). 몸 전체(밥 블록 + 토핑 + 눈·입·발)가 **`SushiJoint`라는 Motor6D 딱 하나**로 `HumanoidRootPart`에 통째로 붙는다(`SushiBody.JOINT_NAME = "SushiJoint"`). `src/client/fx/CharacterFxController.luau`가 이미 "보이는 모든 초밥 캐릭터의 `SushiJoint`(Motor6D).Transform만 바꿔요"라고 명시한다.

**즉 팔다리를 따로 움직이는 전통적인 춤 애니메이션(Roblox `Animation`/`AnimationTrack`)은 이 캐릭터 구조로는 만들 수 없다.** 가능한 건 `VictoryCutsceneLogic.dollPose`가 이미 하고 있는 것과 같은 방식 — **온몸을 하나의 강체로 보고 시간에 따른 자세 함수(위치 오프셋 + pitch/yaw/roll)를 계산해 `SushiJoint.Transform`에 대입**하는 것뿐이다. 이건 제약이자 동시에 좋은 소식이다:
- 폴가이즈의 빈(Bean) 캐릭터도 팔다리가 사실상 없는 말랑한 덩어리라 춤이 "통통 튀고 기울고 흔들리는" 전신 모션 위주다 — 우리 제약과 톤이 잘 맞는다.
- 기존 `VictoryCutsceneLogic`·`EliminationCutsceneLogic` 패턴(순수 함수 모듈 + `os.clock()` 기준 로컬 타이밍, `src/client/fx/VictoryCutsceneController.luau:224` 참고)을 그대로 재사용할 수 있어서 **새 애니메이션 파이프라인이 필요 없다.**

**제안**: 신규 순수 모듈 `EmoteLogic.luau`(`shared/`, Roblox API 없음) — `poseAt(emoteId, t, duration) -> { dy, pitch, yaw, roll }` 같은 형태로 `VictoryCutsceneLogic.dollPose`와 동일한 패턴. 카탈로그는 `EmoteCatalog.luau`(`FxCatalog.luau`와 같은 구조: `id, displayName, tier, productId?, coinPrice?`).

## 3. 이모트(감정표현) 시스템 설계

### 3.1 트리거 방식
- **터치 버튼을 늘리지 않는다** (CLAUDE.md·GDD 6 "터치 버튼은 점프·다이브·잡기 3개만"이 확정 원칙이고, 이모트는 애초에 달리는 라운드 중 금지라 터치 버튼 자리가 필요 없다 — 아래 3.2).
- 로블록스 공식 이모트도 버튼 입력이 아니라 **전용 메뉴**로 연다(`REFERENCE-emotes.md` 1절). 같은 패턴을 따라 **"🍣 스킨" 버튼 옆에 "😊 표정" 버튼**을 하나 더 둔다(로비·대기실·관전·대기석에서만 활성화된 상태로 보이고, 달리는 중엔 숨기거나 비활성 — 스킨 탈의실과 똑같은 가시 규칙, GDD 10 "UI 목록" 재사용).
- 눌리면 **이모트 휠**(2행 카드 격자, 최대 8개 장착 — Roblox `SetEquippedEmotes`의 "최대 8개" 상한과 같은 근거로 통일) 패널이 뜬다. PC는 숫자 키 1~8로 빠른 트리거도 추가 가능(선택).
- 게임패드: D-패드 또는 지정 버튼으로 같은 패널을 연다(점프/다이브/잡기 버튼과 겹치지 않음, 어차피 달리는 중엔 못 씀).

### 3.2 사용 가능 시점 / 금지 시점
- **허용**: 로비, 방 대기실, 관전(탈락 뒤), 대기석(통과 뒤), 라운드 소개 전(카운트다운 "출발!" 뜨기 전까지).
- **금지**: 라운드 소개 플라이스루(카메라 고정), 출발한 레이서(RoundActive), 탈락 연출·우승 연출 재생 중.
- **이 경계는 완전히 새로 만들 필요가 없다** — `src/server/ShopService.luau:60` `ShopService.isLocked(player)`가 **정확히 같은 경계**(라운드 중·연출 중 장착 금지)를 이미 판단하고 있다. 서버 신규 리모트 `EmoteRequest(emoteId)`가 이 함수(또는 공용으로 뽑아낸 헬퍼)를 그대로 재확인하면 된다 — GDD 9.1의 "장착·코인 해금을 거절한다" 잠금과 **같은 신뢰 경계**를 그대로 물려받는 설계다.
- **판정에 영향 없음을 보장하는 핵심 규칙**: 이모트 재생 중에도 `WalkSpeed`·`JumpPower`·히트박스는 전혀 건드리지 않는다(Fortnite처럼 "이모트 중 무방비"를 만들지 않음 — 어차피 라운드 중엔 못 쓰므로 무방비가 될 "전투" 자체가 없다). 이동을 시작하면 이모트는 즉시 끊긴다(로블록스 엔진 기본 관행과 동일, `REFERENCE-emotes.md` 1절).

### 3.5 저작권 메모 (반드시 지킬 것)
- `REFERENCE-emotes.md` 3절: Fortnite는 플로스(Backpack Kid)·밀리락(2 Milly)·칼튼 댄스(Alfonso Ribeiro)·오렌지 저스티스를 그대로 넣었다가 여러 건 소송을 당했고, 소송 자체는 절차적 이유로 멈췄을 뿐 "안무는 저작권 대상이 아니다"가 법적으로 확정된 적이 없다.

## 4. "통과자 세레모니" 설계

### 4.1 자동 재생 vs 플레이어 선택 — 1차는 **자동 재생 먼저** 추천
- **이유**: §1 진단의 "비대칭"을 가장 빨리, 가장 적은 리스크로 메우는 방법이다. 전원 같은 무료 세레모니 하나만 있으면 구현·테스트 범위가 작다(순수 로직 + 클라이언트 연출만, 서버 판정·경제 변경 없음).
- **그다음 배치**(선택형)에서 "3.1~3.4의 이모트 중 하나를 통과 세레모니로 지정"하는 유료 커스터마이즈를 얹는다 — m5-09(연출 팩: 탈락 "고양이 손님", 우승 "불꽃놀이")와 완전히 같은 패턴이라 재사용이 쉽다. 즉 **1차: 자동 전용 → 2차: 선택 커스텀(이모트 연동)**.
- 이렇게 나누는 또 다른 이유: 업계에 "통과 즉시 자동 재생되는 세레모니"의 선례가 확실치 않다(`REFERENCE-emotes.md` 4절 — 폴가이즈는 텍스트, 스텀블가이즈는 플레이어가 직접 트리거). 작게 시작해서 반응을 보는 게 안전하다.

### 4.2 판정과의 분리 — 순수 로직 분리 (`PassCeremonyLogic` 제안)
`EliminationCutsceneLogic`·`VictoryCutsceneLogic`과 똑같은 패턴으로 신규 순수 모듈을 제안한다(Roblox API 없음, `shared/`):

```
PassCeremonyLogic.DURATION = 2.2            -- 기본값, 플레이테스트 후 조정
PassCeremonyLogic.timeline(duration)        -- Beat 목록: 효과음("Qualified", 이미 있음) + 말풍선 시점
PassCeremonyLogic.poseAt(t, duration)       -- EmoteLogic.poseAt("rice-shower-cheer", t, duration)에 위임(기본 세레모니 = 위 11번 "밥알 비 세레모니")
PassCeremonyLogic.canStartWorld(activeCount) -- EliminationCutsceneLogic.canStartWorld와 같은 동시 재생 한도(제안 10개 — 대기석엔 최대 24명이 몰릴 수 있어 탈락 한도 6보다 넉넉하게)
```

**중요한 설계 결정 — 세레모니는 결승선이 아니라 "도착한 대기석"에서 재생한다.** 지금 서버 코드(`RoundService.luau:305-311`)는 **판정과 텔레포트가 같은 프레임**이고, GDD 4장은 "통과하면 바로 코스 밖 대기석으로 옮겨져… **남은 사람을 방해할 수 없어요**"라고 명시한다. 탈락 연출처럼 결승선에서 3초간 캐릭터를 멈춰 세우면(`EliminationService.eliminate`의 anchor-then-delay 패턴) 아직 달리는 레이서의 시야·충돌을 방해할 위험이 있다. 그래서:
- **서버 판정·텔레포트는 지금 그대로**(한 프레임, 변경 없음) — 리스크가 가장 낮은 선택.
- 클라이언트 `PassCeremonyController`(신규, `EliminationCutsceneController`와 자매 모듈)가 기존 `PlayerResult`("Passed") 이벤트를 구독해(`Sfx.luau:461`와 같은 지점에 나란히 추가), **텔레포트가 끝나 이미 대기석에 있는 캐릭터 위에서** 2.2초짜리 연출을 로컬로 재생한다. 서버는 "누가 몇 등으로 통과했는지"만 알려주고, 연출 자체는 결과 방송을 들은 모든 클라이언트가 각자 로컬 시계(`os.clock()`)로 동시에 틀어서 보이는 것을 맞춘다(지금 `VictoryCutsceneController.luau:224`가 이미 쓰는 바로 그 방식).
- 대기석(=`LobbySpawn`, 같은 라운드에 통과한 다른 사람들과 탈락 뒤 관전하는 사람들이 모이는 바로 그 자리)에서 재생되니, **방 전원이 볼 수 있는 자리**에서 자연스럽게 터진다 — 결승선을 막지 않으면서도 사회적 순간은 그대로 살린다.

### 4.3 길이
- **2~2.5초 제안**(탈락 3초보다 짧게). 근거: 탈락은 "그 라운드가 끝났다"는 확정된 순간이라 충분히 음미해도 되지만, 통과자는 다음 라운드를 기다리는 대기석에 있을 뿐 매치가 계속 진행 중이다(다른 사람은 아직 달리고 있을 수도 있음) — 너무 길면 다음 라운드 소개 전까지의 "멍 때리는 시간"만 늘어난다. 기존 `Config.Match.EliminationCutscene = 3`과 비슷한 자리에 `Config.Match.PassCeremony = 2.2` 같은 새 값을 추가하는 모양을 제안한다(이름은 developer가 확정).

### 4.4 기본 세레모니 디자인 (무료, 전원 동일)
**"밥알 비 세레모니"**(3.3의 11번과 동일 동작 재사용): 제자리 점프 3번 + 머리 위로 흰 쌀알 파티클이 짧게 흩날림 + 머리 위 말풍선 "통과!"(탈락의 "먹혔다!" 도장과 대칭되는 톤) + 기존 `Sfx.play("Qualified")`를 그대로 재생 시점에 맞춘다(새 효과음 불필요, 이미 있는 자산 재사용). 코인 보상 토스트("🍚 +10")가 뜨는 타이밍과도 겹치니, 색종이 대신 **밥알(쌀알) 모티프**로 보상 UI와 톤을 통일했다.

### 4.5 유료 커스텀 세레모니 (2차 배치, m5-09와 같은 패턴)
- m5-09가 이미 "탈락 연출 팩"·"우승 연출 팩"을 `EliminationFx`/`VictoryFx` Player 속성으로 구현한 전례가 있다(`src/shared/Attributes.luau:30-31`). 같은 구조로 **`PassCeremony`** 속성을 하나 더 추가해, 플레이어가 3.3의 이모트 중 하나(또는 "통과 세레모니 전용" 신규 디자인)를 "통과할 때 자동으로 틀 것"으로 지정할 수 있게 한다.
- 가격은 m5-09가 제안한 연출 팩 가격대(GDD 9.3 "탈락 연출 팩 79~149 R$, 재검토 메모: 49~99로 낮출지")와 같은 구간에서, 3.4의 이모트 개별가(19~29 R$)보다는 약간 높게(예: **49 R$**, "항상 자동으로 터지는 연출"이라는 프리미엄) 매기는 안을 제안한다. 정확한 값은 사용자 확정.

## 5. 사용자 결정 필요

1. **이모트 사용 가능 시점 확정**: 제안(3.2) — 로비·방 대기실·관전·대기석·소개 전까지 허용, 출발한 레이서·소개 플라이스루·연출 중 금지. 이건 GDD 6장(조작)이나 새 소절에 명문화해야 한다.
2. **통과 세레모니를 1차에 자동 전용으로 할지**: 제안(4.1) — 자동 하나 먼저, 선택형 커스텀은 2차. 다른 안을 원하면(처음부터 선택형) 범위가 커진다(m5-09 선행 필요).
3. **세레모니 재생 위치**: 제안(4.2) — 결승선이 아니라 대기석에서(판정·텔레포트 변경 없음). "그래도 결승선에서 잠깐 멈추는 게 낫다"고 하면 GDD 4장의 "남은 사람을 방해할 수 없어요" 원칙과 다시 맞춰야 한다(더 큰 변경, developer와 재검토 필요).
4. **길이**: 2~2.5초 기본값 승인 또는 다른 값.
5. **1차 이모트 12개 중 채택 개수·목록**: 전부 승인할지, 추리거나 더할지. 무료 3종(제안: 꾸벅 인사·단골손님 윙크·덜덜덜)이 맞는지.
6. **가격**: 개별 19/29 R$, 팩 79 R$, 코인 해금 300코인(일반 2종), 세레모니 커스텀 49 R$ — 승인 또는 수정.
7. **UI 동선**: "😊 표정" 버튼을 로비/대기실/관전/대기석에 "🍣 스킨" 버튼과 나란히 두는 안 승인 여부. 터치 버튼은 늘리지 않는다는 원칙 재확인.
8. **밈 재해석 수위**: 3.5의 "리듬·실루엣만 유사, 안무는 완전히 다름" 수준을 기본으로 할지. 더 닮게 하고 싶은 특정 밈이 있으면 그건 별도로 법적 리스크를 다시 짚어야 한다.
9. **VIP 패스 연계**: VIP 전용 이모트 1종을 추가할지(선택 사항, 3.4 끝 메모).
10. **장착 개수 상한**: 이모트 휠에 최대 몇 개를 장착할지(제안: 8개, 로블록스 공식 상한과 동일).

## 6. 요약 — 우선순위 추천
1. **통과 세레모니 자동판 먼저(4절)**: §1 진단이 보여주는 "탈락은 화려한데 통과는 밋밋하다"는 비대칭을 가장 적은 리스크·가장 적은 코드로 메운다. 서버 판정은 전혀 안 건드리고(4.2), 기존 `EliminationCutsceneLogic`/`VictoryCutsceneLogic` 패턴 그대로 재사용한다.
2. **이모트 시스템(3절)**: 무료 3종 + 유료 9종으로 시작, UI는 "🍣 스킨" 버튼 옆에 같은 방식으로 추가(터치 버튼 안 늘림). 통과 세레모니가 먼저 자리 잡은 뒤 커스텀 연동(4.5)으로 이어 붙이면 작업이 한 번에 몰리지 않는다.
3. **저작권(3.5)은 타협하지 않는다** — 12개 전부 "영감만, 안무는 오리지널" 선에서 멈춘 설계이고, 더 닮게 바꾸자는 요청이 오면 그때마다 다시 짚어야 한다.
4. 확정되면 `docs/specs/m5-xx-emotes.md`(이모트 시스템)와 `docs/specs/m5-xx-pass-ceremony.md`(통과 세레모니, 선행 추천)로 나눠 스펙화한다 — 공용 파일(`Attributes.luau`에 `PassCeremony`·이모트 관련 새 속성, `Config.luau`에 `PassCeremony` 길이 값, `Remotes.luau`에 `EmoteRequest`) 수정이 필요하니 CLAUDE.md "병렬 작업 중에는 스펙에 지정된 한 에이전트만" 규칙을 적용해야 한다.
