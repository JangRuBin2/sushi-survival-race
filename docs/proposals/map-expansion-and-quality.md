# 제안서 — 맵 풀 확장 + 구조물 퀄리티 개선

> **이 문서는 검토용 제안이며, GDD 승인 전까지 반영되지 않는다.** `docs/GDD.md`, `docs/specs/`는 수정하지 않았다. 사용자가 마음에 드는 아이디어를 고르면, 그다음 단계로 `docs/specs/m5-xx-map-<id>.md` 식의 스펙 파일을 실제로 써서 개발에 넘긴다(아래 "다음 절차" 참고). 지금 단계에서는 `docs/specs/`에 새 파일을 만들지 않았다.

**배경**: 사용자가 "맵이 너무 적다"며 더 많은 맵과 "구조물 퀄리티 개선"을 요청했고, "초밥 관련된 거 아니어도 된다"고 명시적으로 허락했다(비초밥 테마 환영).

**조사 범위**: 완료된 맵 6개의 실제 구현 코드(`src/shared/maps/*.luau`, 특히 `*Art.luau`), `MapKit`/`MapKitLogic`(장식 시스템·예산), `docs/REFERENCE-map-production.md`, 이미 `ready` 상태인 신규 맵 스펙 3개(`m5-04` 연어알 폭탄, `m5-05` 튀김 냄비, `m5-06` 디저트 냉장고), Roblox 비슷한 장르 게임 3개 이상(아래 1절).

## 1. 기존 맵 "구조물 퀄리티가 낮아 보이는" 원인 진단 (코드 근거)

실제 구현을 읽고 확인한, 추측이 아닌 코드 사실들이다.

### W1. 장식(파츠) 밀도가 맵마다 들쭉날쭉하다
`<Map>Art.luau`에서 장식 파츠를 추가하는 호출 지점(`part(list, …)` / `disc(list, …)` / `add(specs, …)`) 수를 세어 보면:

| 맵 | 장식 호출 지점 수 (추정) |
|---|---|
| `skewer-showdown` | ~37 |
| `rotating-belt` | ~25 |
| `chef-board` | ~24 |
| `soy-swamp` | ~21 |
| `hot-plate` | ~21 |
| `ramen-rapids` | ~15 |

예산(파츠 600개)의 10% 미만만 쓰는 맵이 대부분이다 — 디테일을 더 넣을 여유가 충분히 남아 있는데 안 쓰고 있다는 뜻이다.

### W2. 맵 6개 중 **3개가 파티클·조명을 아예 안 쓴다**
`ParticleEmitter`/`PointLight`/`SpotLight`를 실제로 만드는 코드(`Instance.new(...)`)를 전수 조사한 결과:

| 맵 | 파티클 | 조명 |
|---|---|---|
| `hot-plate` | 김(Steam) — `HotPlate.luau` 47행 | 후드 조명 — 66행 |
| `skewer-showdown` | 없음 | 등롱(Lantern) — `SkewerShowdown.luau` 213행 |
| `ramen-rapids` | 김(Steam) — `RamenRapids.luau` 336행 | 없음 |
| `rotating-belt` | **없음** | **없음** |
| `soy-swamp` | **없음** | **없음** |
| `chef-board` | **없음** | **없음** |

예산은 맵당 파티클 8개·조명 12개인데, 세 맵은 0개를 쓴다. 정적인 색칠된 파츠만 가득한 방처럼 보이는 가장 직접적인 원인이다. 특히 `RotatingBeltArt.addLanterns`(319행 근처)는 종이 등 모양(Lacquer Ball + 검은 뚜껑) 장식을 만들어 두고도 `PointLight`를 안 달아서, 바로 옆 `hot-plate`·`skewer-showdown`이 같은 모양("등"·"램프")에 빛을 넣은 것과 비교하면 빠진 게 티가 난다.

### W3. 맵 전용 분위기(안개·색 보정)가 구조적으로 없다
`Lighting.Atmosphere`를 건드리는 코드는 `src/server/LobbyService.luau`의 `applyLighting`(한 플레이스 모드에서 로비 때 딱 한 번) 뿐이다. `Lighting`은 Roblox의 **전역 싱글턴 서비스**라서, 한 플레이스 모드(`Config.Arena`로 방마다 아레나를 띄워 동시에 돌리는 구조, CLAUDE.md "플레이스 구성")에서는 **같은 서버 안의 여러 방이 서로 다른 맵을 동시에 돌려도 전역 `Lighting.Atmosphere`를 하나만 가질 수밖에 없다** — 구조상 "철판 맵은 뜨거운 주황빛, 와사비 맵은 서늘한 녹색빛"처럼 `Lighting`으로 맵마다 분위기를 바꿀 수 없다. 지금까지 이 제약을 피해 갈 지역적 수단(장식 안개 상자, 색 보정용 반투명 패널 등)도 시도된 적이 없다 — 그래서 6개 맵이 전부 로비와 똑같은 중립 조명 아래 놓인 것처럼 보인다.

### W4. 움직이는 장식이 거의 없다
장식은 전부 `MapKit.applyDecorRules`로 `Anchored = true`가 강제된다(판정과 절대 섞이지 않게 하려는 의도적 설계, 유지해야 함). 그 결과 "제자리에서 도는 간판", "흔들리는 발, 깃발" 같은 저비용 생동감 장치가 하나도 없다. `HotPlateArt`의 기름 자국, `RotatingBeltArt`의 카운터 소품들은 전부 완전히 정적이다. (단, `LobbyService` 주석에 따르면 로비 회전 접시는 **클라이언트가 로컬로 돌린다** — 서버 복제 비용 없이 움직임을 넣는 선례가 이미 있다. 맵에도 같은 패턴을 적용할 수 있다.)

### W5. 카메라 연출(`IntroCamera`) 투자 편차
`rotating-belt`·`hot-plate`·`soy-swamp`·`ramen-rapids`·`ikura-bombs`(스펙 D4)·`tempura-pot`은 4점, `skewer-showdown`만 5점이다. 포인트 수 자체보다 **경유점 간 전환이 직선적**이라(예: `HotPlateArt.introCamera`는 "손님 얼굴 → 층 옆 → 맨 위층 → 바깥"으로 한 방향만 훑는다), 극적인 반전 샷(위→아래, 좁은 틈 통과)이 적다.

## 2. 기존 맵 퀄리티를 올릴 구체적 방향 (예산 안, 판정 변경 없음)

전부 **판정 지오메트리·장애물 수치는 그대로 두고 `<Map>Art.luau`·`build` 안의 장식 추가 코드만** 바꾸는 범위다. 순수 로직 테스트는 영향받지 않는다(장식은 `MapTypes.validate`·게임플레이 판정과 무관).

1. **빠진 파티클·조명부터 채운다 (W2 직접 해결)**
   - `rotating-belt`: `addLanterns`가 만드는 종이 등 파츠에 `PointLight`(따뜻한 주황, Range 25) 부착. 카운터 소스병 옆에 약한 `ParticleEmitter`(간장병 김 아님 — 손님 테이블의 따뜻한 조명 반사 느낌 정도로 Neon 강조).
   - `soy-swamp`: 간장 웅덩이 표면에 거품 `ParticleEmitter`(느리게 보글보글), 와사비 산 꼭대기에 `PointLight`(연두, 와사비 패드가 "맵 위에서도 빛나는 지형지물"로 보이게).
   - `chef-board`: 칼이 지나간 직후 불꽃 튀는 `ParticleEmitter`(짧은 one-shot), 도마 중앙 조명 포인트(요리사 조명이 도마를 비추는 느낌).
   - 예산(파티클 8·조명 12)에 한참 못 미치니 여유 있게 늘릴 수 있다.

2. **장식 호출 지점이 적은 맵(W1)에 "반복 디테일 유닛"을 추가한다**
   - `ramen-rapids`(현재 ~15곳)가 가장 단조롭다. `RotatingBeltArt.addCounterItem`처럼 "작은 소품 하나 + 변형 3종을 루프로 반복 배치"하는 헬퍼를 이식해, 급류 양옆에 그릇·젓가락·고명 소품을 반복 배치한다. REFERENCE-map-production.md 5절이 말하는 "적은 수의 범용 피스를 반복 사용"과 같은 원칙이고, 코드량 대비 체감 디테일이 가장 크게 느는 구간이다.

3. **지역적 "안개 상자"로 맵마다 분위기를 분리한다 (W3 우회)**
   - 전역 `Lighting.Atmosphere`를 못 쓰는 대신, 맵 테두리 바깥에 **아주 크고 옅은 반투명(Transparency 0.85~0.95) 색 패널**(충돌 없음, 기존 장식 규칙 그대로)을 멀리 둘러서 "이 맵만의 색안개"를 흉내 낸다 — 예를 들어 `tempura-pot`은 냄비 벽 바깥에 옅은 금빛 반투명 벽, `dessert-fridge`는 옅은 하늘색. 전역 서비스를 건드리지 않아 한 플레이스 모드의 동시 다중 아레나와 충돌하지 않는다. 비용은 파츠 1~2개뿐이라 예산에 영향이 거의 없다.
   - (참고) `Config.Arena`에 "슬롯마다 독립 `Atmosphere`"를 지원하는 것은 Roblox API 제약(진짜 로컬 안개는 `Lighting` 싱글턴뿐)상 불가능하다고 확인했다 — 이 방향은 코드로 해결할 수 없는 영역이라 제외한다.

4. **움직이는 장식을 클라이언트 로컬 애니메이션으로 추가한다 (W4)**
   - `LobbyService`/`LobbyFxController`의 "서버는 정지, 클라이언트가 로컬로 회전시킨다" 패턴을 맵에도 적용: 예를 들어 `rotating-belt`의 손님 얼굴 눈 깜빡임, `hot-plate`의 선반 위 간장병이 살짝 흔들리는 정도. 서버 복제 비용이 없어 예산(파츠 수)에도 잡히지 않는다. 신규 맵 스펙 중 `tempura-pot`이 이미 "젤리가 출렁이는 장식 애니메이션(크기만, 판정 파츠는 고정)"을 이 패턴으로 쓰기로 했으니(m5-06 아님 m5-05였나 확인: 실제로는 m5-06의 Jelly 설명에 있음) 같은 패턴을 기존 6개 맵에도 거꾸로 적용하면 된다.

5. **`IntroCamera` 경유점에 "반전 샷"을 하나씩 넣는다 (W5)**
   - 예: `hot-plate`처럼 아래(손님 입)에서 올려다보는 샷은 이미 좋은 사례다. 이 패턴을 다른 맵에도: `rotating-belt`에 병목 위에서 아래로 내려다보는 샷, `soy-swamp`에 와사비 산 정상에서 내려다보는 샷을 추가.

이 5가지는 전부 **기존 맵의 `done` 상태(스펙 상태)를 건드리지 않고** 개발자가 "퀄리티 패스" 스펙 한두 개(예: `m5-xx-map-quality-pass.md`)로 묶어 처리할 수 있는 범위다. 수치·판정 변경이 없어서 QA도 "시각적으로 전과 같은 체감인지"만 보면 된다.

## 3. 신규 맵 아이디어 (15개)

Race/Survival/Final을 섞고, 사용자가 허락한 대로 비초밥 테마도 섞었다. 기존 9개(완료 6 + 예정 3: `ikura-bombs`·`tempura-pot`·`dessert-fridge`)와 **기믹·비주얼이 겹치지 않는 이유**를 각각 적었다. 전부 임시 id이고, 수치는 전혀 정하지 않았다(그 단계는 실제 스펙 작성 때).

### Race (결승선 통과, 최대 90초) — 기존 4개(회전 벨트: 역주행 벨트 / 간장 늪: 감속·웅덩이 / 라멘 급류: 전진 밀림·건너기 / 디저트 냉장고: 얼음 관성)

1. **`sushi-boat-rapids` (스시보트 급류)** — Survival 아님, Race. rule: "보트를 갈아타며 급류를 건너요." 핵심 기믹: 고정된 플랫폼이 아니라 **서로 다른 속도로 평행 이동하는 좁은 보트(컨베이어처럼 왕복)** 사이를 점프로 갈아타는 타이밍 게임. 기존 라멘 급류(차슈 발판은 "가라앉았다 떠오름", 수직)와 달리 이건 **좌우 왕복**이라 손맛이 다르다. (참고: `m4-04 R1` 결정 — 막힌 구간 없게 항상 느린 보조 길 병행.)
2. **`roller-coaster-dash` (롤러코스터 질주)** — 비초밥. rule: "레일 위 트럭을 타고 달리다 구간마다 내려서 달려요." 레일 구간(자동으로 밀려감, 장애물만 피하면 됨)과 도보 구간(직접 달림)이 번갈아 나오는 **리듬 변화형** Race — 회전 벨트(계속 저항)·간장 늪(계속 감속)과 달리 "힘을 아예 안 써도 되는 구간"이 있다는 게 차별점.
3. **`conveyor-factory` (초밥 공장 컨베이어)** — 초밥이지만 비주방 테마(공장). rule: "기계 팔을 피해 컨베이어 공장을 가로질러요." 머리 위에서 수직으로 내려찍는 **프레스 기계 팔**(젓가락 집기의 수직 버전이 아니라 "맞으면 넓은 구역이 통째로 아래로 꺼짐" — 함정형) + 좌우로 미는 포장 로봇 팔. 회전 벨트의 젓가락(집어 올림)과 달리 **바닥이 사라지는 함정**이라 리스크가 다르다.
4. **`bouncy-castle-maze` (방방 미로)** — 완전 비초밥. rule: "말랑한 바닥 위를 튕기며 미로를 빠져나가요." 바닥 전체가 트램펄린(강제 바운스, 멈춰 서 있을 수 없음)이라 **정지 자체가 불가능한 Race** — 다른 4개 맵은 전부 "멈추면 느려질 뿐"인데 이건 "멈출 수가 없어서" 조작 난도가 다르다. 얼음(디저트 냉장고, 멈추기 어려움)과 비슷해 보이지만 얼음은 관성/수평이고 이건 수직 바운스 강제라 겹치지 않는다.
5. **`lantern-bridge` (등불 다리 건너기)** — 초밥 아님(일본풍 축제). rule: "흔들리는 다리와 종이 등불 사이를 건너요." 여러 개의 **흔들리는 구름다리**(좌우로 흔들리는 외나무다리, 두 명 이상 타면 더 심하게 흔들림 — 군중 압박감)를 건너는 Race. 다른 맵과 달리 **다른 플레이어의 존재 자체가 장애물 강도를 올리는** 유일한 맵(몰릴수록 위험).

### Survival (목표 인원만 남을 때까지 버티기, 최대 60초) — 기존 2+1개(철판: 계속 움직이기 / 도마: 줄 읽고 피하기 / 튀김 냄비: 올라가서 자리 지키기)

6. **`spinning-plates` (접시 돌리기 재주)** — 초밥, GDD 5.3 팀 라운드 아이디어("접시 쌓기")와는 다른 1인 버전. rule: "돌아가는 접시 위에서 버텨요." 바닥 전체가 **회전하는 원반**(철판은 안 움직이고 타일이 사라짐, 도마는 안 움직이고 칼이 지나감 — 이건 바닥 자체가 계속 회전해 원심력으로 바깥으로 쓸려나감)인 Survival. 가운데로 모일수록 안전하지만 좁다는 자리싸움.
7. **`giant-jenga` (와르르 나무 블록)** — 비초밥. rule: "흔들리는 블록탑 위에서 안 떨어지게 버텨요." 쌓인 나무 블록이 무작위로 하나씩 **빠지면서 탑 전체가 기울고 흔들리는** Survival — 도마의 "기울기"(전체가 같이 기움)와 달리 이건 **부분부분 다르게 흔들려서 무게중심을 계속 옮겨야** 함.
8. **`umbrella-rain` (장맛비 우산 지붕)** — 비초밥. rule: "비를 피해 우산 지붕 위를 옮겨 다녀요." 펼쳐진 우산들이 지붕처럼 떠 있고, 빗물이 고이면 그 우산이 **기울어 미끄러뜨림**(탈락은 아니고 다음 우산으로 밀려남) + 번개가 치는 자리는 경고 뒤 그 우산만 접혀 사라짐. 튀김 냄비(차오르는 액체+올라가기)와 달리 **올라가는 목표가 없는 수평 이동형** Survival.
9. **`cat-cafe-shelves` (고양이 카페 캣타워)** — 완전 비초밥. rule: "흔들리는 캣타워 선반 위에서 버텨요." 여러 높이의 좁은 선반(발판)에 거대 고양이들이 지나다니며 선반을 건드려 흔들거나(판정은 코드가 계산하는 좌우 밀림), 선반 위 장난감 공이 굴러다니며 맞으면 밀려남. 튀김 냄비처럼 "올라가기"가 아니라 **좁은 선반 사이를 옆으로 옮겨 다니며 버티는** 수평형.
10. **`windmill-fields` (풍차 들판 피하기)** — 비초밥. rule: "돌아가는 풍차 날개를 피해 버텨요." 지면은 고정(철판·도마처럼 사라지지 않음)이고, 여러 **대형 풍차 날개**(회전 꼬치 쇼다운과 달리 지면 위, 수평이 아니라 수직 원 궤도로 휩쓺)가 지나가는 자리를 피해 서 있어야 하는 Survival — "바닥이 멀쩡한데 위험이 공중에서 온다"는 점이 철판·도마(바닥이 사라짐)·튀김 냄비(액체가 차오름)와 다르다.

### Final (마지막 1명 생존, 90초 뒤 연장전 필수) — 기존 1+1개(회전 꼬치: 옆에서 오는 꼬치를 점프로 넘기기 / 연어알 폭탄: 위에서 오는 위험을 읽고 자리 옮기기)

11. **`tug-of-war-platform` (줄다리기 발판)** — 초밥. rule: "발판이 기울며 한쪽 끝으로 미끄러져요." 거대한 시소/저울 모양 발판이 **살아남은 인원의 무게 분포에 따라 기우는** Final — 무게(= 남은 인원 수와 위치)로 판정이 계산되는, 꼬치·폭탄과 달리 "남이 어디 서 있는지가 내 위험도를 바꾸는" 유일한 결승. 연장전 훅: 기울기 폭과 속도를 20초 동안 극단으로 올려 반드시 한쪽 끝으로 쓸려나가게.
12. **`drum-circle-collapse` (북 장단 붕괴)** — 비초밥(축제/타악기). rule: "장단에 맞춰 북이 하나씩 꺼져요." 원형으로 배치된 거대 북들을 발판으로 삼는데, 리듬(점점 빨라지는 BPM)에 맞춰 북이 "쿵" 소리와 함께 꺼졌다 다시 솟아오르는 패턴형 Final — 꼬치(회피)·폭탄(랜덤 타격)과 달리 **패턴을 외우면 완전히 안전한**, 리듬 게임에 가까운 결승. 연장전 훅: 꺼지는 패턴이 솟아오르지 않고 영구히 사라지는 비율이 20초 동안 100%로.
13. **`sinking-ship-deck` (침몰하는 배 갑판)** — 비초밥. rule: "기울어 가라앉는 갑판에서 버텨요." 배 갑판이 서서히 한쪽으로 기울며 침수(바닷물 높이가 차오름, 연어알 폭탄의 "접시가 작아짐"과 달리 **경사 + 수위 상승이 동시에** 진행) — 미끄러져 떨어지는 건 디저트 냉장고(얼음, Race)와 비슷한 감각이지만 이쪽은 Final이라 "최후 1인"이 걸려 있고 침수라는 별개 탈락 조건이 겹친다.
14. **`claw-machine-prize` (인형뽑기 기계 속)** — 완전 비초밥. rule: "집게가 훑고 지나가는 유리 상자 안에서 버텨요." 투명한 유리 상자 안, 쌓인 인형 더미 위에서 거대한 **집게(claw)**가 주기적으로 내려와 닿은 구역을 통째로 들어 올려 떨어뜨리는 Final — 셰프 손(연출 전용, 탈락 처리만)과 달리 **집게가 직접 판정 지오메트리를 들어 옮기는 장애물**이라 메커니즘이 다르다. 연장전 훅: 집게가 상자 전체를 기울여 쏟아버림.
15. **`fireworks-finale` (불꽃놀이 피날레)** — 비초밥(축제). rule: "터지는 불꽃을 피해 지붕 위에서 버텨요." 여러 건물 옥상(서로 다른 높이, 좁은 다리로 연결)을 오가며 하늘에서 떨어지는 **불꽃 파편**(연어알 폭탄과 달리 포물선으로 **옆에서 날아와** 떨어지는 지역 판정, 경고는 꼬리 이펙트)을 피하는 Final — 폭탄(수직 낙하, 접시 축소형 결승)과 달리 **옥상 사이 이동 자체가 메인 리스크**(다리가 좁음)이고 축소가 없다(불꽃이 계속 늘어나는 밀도형 서든데스).

> 비율 메모: Race 5개(그중 2개 완전 비초밥), Survival 5개(그중 3개 완전 비초밥), Final 5개(그중 3개 완전 비초밥) — 총 15개 중 8개가 완전 비초밥 테마다. "초밥집 전체 테마" 긴장은 4절에서 따로 다룬다.

## 4. 사용자 결정 필요

1. **전체 테마 일관성**: 로비·캐릭터(초밥)·탈락 연출(젓가락·손님 입·셰프 손)은 전부 "초밥집" 세계관인데, 개별 맵이 롤러코스터·방방·캣타워·북 장단처럼 완전히 동떨어진 테마여도 괜찮은가? 두 방향이 있다:
   - (A) **"초밥 가게가 통째로 테마파크"라는 틀로 감싼다** — 예: 롤러코스터는 "가게 옆 유원지", 캣타워는 "옆집 고양이 카페", 불꽃놀이는 "가게 마당 축제". 탈락 연출(젓가락·손님 입·셰프 손)은 그대로 유지하면 "어디서 떨어져도 결국 초밥집으로 돌아온다"는 통일감이 남는다.
   - (B) 테마를 완전히 자유롭게 풀어준다 — Fall Guys도 왕관·중세·우주 테마가 섞여 있으니 파티 게임 장르에서는 흔한 선택이다.
   - 레퍼런스(Deathrun)는 테마를 안 맞추는 쪽이고, Fall Guys는 "파티 게임"이라는 톤만 맞추고 세계관은 안 맞춘다. 이 프로젝트는 GDD 3장에 "초밥이 되어 달리는" 정체성이 명확히 박혀 있어서(캐릭터·탈락 연출·우승 연출 전부 초밥집 모티프), 완전히 자유로운 B보다는 A에 가깝게 "탈락·우승 연출만은 항상 초밥집"으로 묶는 절충을 제안하지만, 확정은 사용자 몫이다.
2. **맵 풀 규모의 관리 부담**: 맵 하나 = `*.luau` 3~4개 + 테스트 1개 + QA 1라운드 + Studio 확인(사용자 시간) + 소리 id 선정(사용자 할 일, `USER-TODO.md`)이 계속 늘어난다. 지금도 M5 신규 맵 3개가 "ready"에서 대기 중이다. 15개를 한 번에 스펙화하면 사용자 확인 부담이 커지므로, **한 번에 2~3개씩 우선순위를 골라 스펙화 → 개발 → 다음 배치**를 제안한다(5절 "다음 절차" 참고). 우선순위를 사용자가 정해 주면 그 순서로 간다.
3. **맵 종류 균형**: 지금 9개(완료+예정) 기준 Race 4 / Survival 3 / Final 2다. GDD 5.1상 라운드 구성(Race는 매 판 최소 1~2번 필요, Survival은 4라운드일 때 최소 1번, Final은 매 판 정확히 1번)을 생각하면 Final은 풀이 2개만 있어도 "결승 맵 중복 없음" 규칙(한 판 안에서라 사실 상관없음 — 결승은 한 판에 1번뿐)과는 안 부딪히지만, **여러 판을 연달아 하면 Final 맵이 금방 질릴 수 있다**(풀 2개면 50% 확률로 반복). 이번 제안 15개 중 Final 5개를 포함한 이유이기도 하다. 전부 다 만들 필요는 없고, 어떤 종류부터 늘릴지 사용자가 우선순위를 정하면 된다.
