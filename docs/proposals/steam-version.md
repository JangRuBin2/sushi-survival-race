## 0. 한 줄 요약

로블록스판은 **계속 운영하면서 기획·재미를 검증하는 시험장**으로 두고, 스팀판은 **Unity 6**로 새로 만든다. 처음부터 큰 게임을 만들지 않고 **조작감 → 8명 네트워크 → 데모 → 스팀 Next Fest → 반응을 보고 전용 서버·정식 출시** 순서로, 단계마다 "계속할지"를 정하는 관문을 둔다. 초기 서버비는 **0원**(스팀 P2P + Valve 중계), 공개 매칭(전용 서버)은 동시접속이 생긴 뒤에 붙인다.

## 2. 로블록스판에서 무엇을 가져가나

로블록스 코드(Luau + Roblox API)는 그대로 돌릴 수 없다. 하지만 **순수 로직으로 분리해 둔 부분은 C#으로 거의 1:1 옮길 수 있고, 테스트도 같이 옮긴다** — 기획이 이미 검증돼 있다는 게 가장 큰 자산이다.

| 구분 | 로블록스판 파일 | 스팀판에서 |
|---|---|---|
| **그대로 이식** (순수 로직 + 테스트) | `Rules`(라운드 수·통과 인원·판 계획), `RoundLogic`(종료 판정·구제·등수), `SpectateLogic`, `DiveLogic`, `GrabLogic`, `AttackLogic`(대상·쿨다운·면역), `DynamiteLogic`, `RaceActionLogic`, `RewardLogic`, `DrawLogic`, `Skins` 카탈로그 데이터, `LocalizeLogic` + `Strings.csv` | C# 순수 어셈블리로 옮기고 lune 테스트를 xUnit/NUnit 테스트로 옮긴다 |
| **설계만 참고** (다시 구현) | 맵 26개의 규칙·장애물 패턴(`<Map>Layout`/`<Map>Logic`), 방 시스템, 관전, 탈락·우승 연출 흐름, 게임패드 UI 규칙, 터치 UI(나중) | Unity 씬·프리팹·컴포넌트로 다시 만든다. 맵 수치(길이·폭·시간)는 출발점으로 쓴다 |
| **새로 만든다** | — | 물리 캐릭터 컨트롤러, 네트워크 동기화(예측·보정), Steamworks 연동, 아트·애니메이션·사운드 전부, 저장(스팀 클라우드), 설정 메뉴(그래픽·키 바꾸기) |

> 이식한 순수 로직이 로블록스판과 같은 답을 내는지 **같은 테스트 케이스로 고정**하면, 앞으로 기획을 바꿀 때 두 판을 같이 맞추기 쉽다.

## 3. 기술 구조

### 3.1 엔진·기본 설정
- **Unity 6 (LTS)**, 렌더 **URP**(스팀덱·저사양 PC 대응, 나중에 콘솔도 쉬움), 입력 **Input System**(키마·게임패드 한 번에 — 로블록스판 게임패드 UI 규칙을 그대로 가져갈 수 있음).
- 라이선스: **Unity Personal은 최근 12개월 매출·투자 $200,000 미만이면 무료**. 넘으면 Pro(좌석당 연 $2,310부터, 2026-01 5% 인상 반영).
- 저장소: **새 저장소**(예: `sushi-run-steam`) 권장 — Unity 프로젝트는 크고(아트·씬), 큰 파일은 Git LFS가 필요하다. 로블록스 저장소에는 이 제안서와 공통 기획만 둔다. (9절 Q1)

### 3.2 네트워크 — 단계별로
판정은 지금처럼 **서버(호스트) 권위**를 지킨다(결승선·탈락·순위·보상). 다만 "서버"가 단계마다 다르다.

| 단계 | 구조 | 서버비 | 쓰는 곳 |
|---|---|---|---|
| 1~3단계 | **호스트 방식(Listen server)** — 방장 PC가 서버 겸 플레이어. 연결은 **스팀 네트워킹 + Steam Datagram Relay(Valve 중계, 스팀 개발자에게 무료)** — IP 노출·NAT 문제 없음 | **0원** | 친구 초대 비공개 방, 데모, 플레이테스트 |
| 5단계~ | **전용 서버(Dedicated)** — 리눅스 헤드리스 빌드를 서버 호스팅 업체에서 판마다 띄움 | 동시접속에 비례 (5절) | 공개 매칭·40명 방·랭크 |

같은 코드가 두 구조에서 돌게 처음부터 **"서버 역할" 코드와 "클라이언트 역할" 코드를 나눠** 짠다(로블록스판 server/client 분리와 같은 습관).

**캐릭터 동기화 원칙** (로블록스판에서 배운 것 그대로):
- 내 캐릭터는 **클라이언트가 먼저 움직이고(예측) 서버 결과로 살짝 보정**, 남의 캐릭터는 **보간**해서 부드럽게.
- 넘어짐·튕김은 **서버가 상태(넘어짐 1초, 넉백 속도)만 정하고**, 흐느적거리는 래그돌은 **각자 화면 연출**로 — 래그돌 관절을 네트워크로 맞추지 않는다(대역폭·불일치 지옥 방지). 로블록스판 `PlatformStand` + 클라이언트 연출과 같은 전략.
- 움직이는 장애물은 **서버 시각 기준 공식**(시작 시각 + 주기)으로 각자 계산 → 위치를 계속 보낼 필요 없음.

**넷코드 라이브러리 후보** (2단계에서 짧게 비교 측정 후 결정, 9절 Q6)

| 후보 | 비용 | 장점 | 걱정 |
|---|---|---|---|
| **Netcode for GameObjects** (Unity 공식) | 무료 | 공식 문서·예제, Unity 서비스와 연동 | 원래 "작은 규모 협동 게임"용 — 40명 물리에서 성능 확인 필요 |
| **Fish-Net** (오픈소스) | 무료 | 예측·보정 내장, 40명 규모 사례, 소스를 직접 고칠 수 있음 | 커뮤니티 지원 중심 |
| Photon Fusion | 동시접속(CCU) 과금 | 예측·지연 보정이 강함 | 사람이 늘수록 비싸짐 — 지금은 보류 |

권장: 2단계에서 **NGO와 Fish-Net 둘로 같은 장면(8명→가짜 40명 봇)을 만들어 대역폭·서버 틱 비용을 재고** 고른다. 스팀 연결은 두 라이브러리 모두 스팀 전송 계층(트랜스포트) 플러그인이 있다.

### 3.3 스팀 연동 (Steamworks)
- 라이브러리: Steamworks.NET 또는 Facepunch.Steamworks.
- 1~3단계에 쓰는 것: **로비·친구 초대**(방 코드 대신 "친구 초대"가 기본), **스팀 네트워킹(SDR)**, **업적**, **스팀 클라우드 저장**, **Steam Playtest**(데모 전 비공개 테스트).
- 나중: 스팀 인벤토리(꾸미기 아이템 거래를 원할 때만), 리더보드.

### 3.4 저장·경제
- 1~4단계는 **경제 서버 없음**: 설정·기록·해금은 스팀 클라우드 + 로컬. 스킨은 **플레이로 해금**(코인·승수·업적).
- 코인·스킨 판매처럼 조작되면 안 되는 경제는 **전용 서버 단계에서** 서버 저장으로 옮긴다(로블록스 `DataService` 역할). 그 전에는 "치트해도 남에게 손해가 없는" 것만 로컬에 둔다.

### 3.5 개발 방식 (Claude + 사용자)
- **순수 C# 로직**은 `UnityEngine`을 참조하지 않는 별도 어셈블리(asmdef)로 두고, **클라우드 세션에서 `dotnet test`로 검증**한다 — 지금 lune 테스트처럼 Claude가 혼자 돌릴 수 있다.
- **씬·프리팹·조작감·그래픽**은 Unity 에디터가 필요해서 **사용자가 에디터에서 확인**한다(지금의 "Studio 확인"과 같은 역할). 각 스펙에 "에디터에서 확인할 것" 목록을 둔다.
- 기존 협업 흐름(planner 스펙 → developer 구현 → qa → docs-writer)을 그대로 쓴다.

## 4. 단계별 계획 (추천 순서)

각 단계 끝에 **관문(계속 / 고침 / 멈춤)** 을 둔다. 관문을 못 넘으면 다음 단계로 가지 않는다.

### 0단계 — 문서·결정 (지금)
- 이 제안서 + 9절 결정.
- 끝: 엔진(Unity, 결정됨)·저장소·수익 모델·아트 방향 답.

### 1단계 — 조작감 시제품 (혼자, 오프라인)
- 물리 캐릭터 컨트롤러: 달리기·점프·**다이브·잡기·공격**·넘어짐(래그돌 연출)·일어나기, 카메라.
- 회색 박스 맵 2개: **회전 벨트(Race)** + **회전 꼬치 쇼다운(Final)** — 로블록스판에서 반응이 확인된 규칙.
- 순수 로직 이식 시작: `Rules`·`RoundLogic`·`DiveLogic`·`GrabLogic`·`AttackLogic` + 테스트.
- **관문**: 그래픽 없이 회색 박스만으로도 "부딪히고 넘어지는 게 웃긴가?" — 사용자 + 지인 몇 명이 직접 해 보고 판단. 아니면 조작감을 고칠 때까지 여기서 반복.

### 2단계 — 네트워크 시제품 (8명, 스팀 P2P)
- 스팀 친구 초대 방(호스트 방식, SDR) → 라운드 흐름(Race → Final, 통과·탈락·관전·우승) 한 판.
- 넷코드 후보 2개 비교 측정(3.2) → 결정.
- **관문**: 지연 100~150ms에서도 내 캐릭터가 끊기지 않고, 넘어짐·잡기 판정이 억울하지 않은가.

### 3단계 — 수직 슬라이스 (데모 품질)
- **아트 기준을 정하는 단계**: 캐릭터(계란초밥 + 스킨 몇 종), 맵 2~3개를 최종 퀄리티로, 소리·UI·메뉴·설정, 스팀덱 확인.
- 스팀 상점 페이지 개설(Steam Direct 앱당 $100), 위시리스트 모으기 시작, **Steam Playtest**로 비공개 테스트.
- **관문**: 플레이테스트 지표(한 판 더 하기 비율, 평균 판 수) + 위시리스트 증가 추세.

### 4단계 — 데모 공개 · Steam Next Fest
- 맵 4~6개, 친구 방 + 봇으로 빈자리 채우기.
- **관문 (가장 중요)**: 데모 동시접속·위시리스트로 **정식 출시 범위와 전용 서버 여부**를 정한다. 반응이 작으면 "친구와 하는 파티 게임(P2P만, 서버비 0)"으로 출시하는 선택지도 있다.

### 5단계 — 전용 서버·공개 매칭 (조건부)
- 조건: 4단계에서 공개 매칭을 감당할 수요가 확인될 때.
- 리눅스 헤드리스 서버 빌드, 호스팅 업체 연결(5절), 매치메이킹, 봇, 안티치트, 서버 저장 경제.

### 6단계 — 정식 출시 · 운영
- 맵 확장(로블록스판에서 반응 좋은 맵부터), 시즌·꾸미기, 콘솔 검토.

> 기간은 일부러 적지 않았다 — 1단계 관문을 넘기 전에는 추정이 의미가 없다. 1단계가 끝나면 2~4단계 일정을 다시 잡는다.

## 5. 서버 비용

### 5.1 1~4단계: 0원
호스트 방식 + Valve 중계(SDR)는 스팀 개발자에게 무료라 서버비가 없다. 드는 돈은 Steam Direct $100, (필요하면) 에셋·외주·테스트 기기뿐.

### 5.2 5단계(전용 서버): 대략 계산
**가정** (실제는 2단계 측정으로 바꾼다): 40명 한 판에 서버 CPU 약 1코어, 플레이어 1명당 서버 송신 약 40kbps(초당 20~30번 상태 전송), 일반 클라우드 요금(CPU 1코어·시간 약 $0.04, 송신 트래픽 GB당 약 $0.09), 환율 약 1,400원.

→ **동시접속 1명·1시간 ≈ $0.003 (약 4원)**, 그중 트래픽이 연산보다 크다.

| 평균 동시접속 | 월 서버비 (대략) | 비고 |
|---|---|---|
| 100명 | 약 30만 원 | 이 정도면 대기열이 비기 쉬움 → 봇 필수 |
| 1,000명 | 약 300만 원 | |
| 10,000명 | 약 3,000만 원 | 이 규모면 매출도 큼 |

- **지역별 최소 서버**(아시아·북미·유럽)를 켜 두는 고정비가 월 수십만 원 붙는다.
- **줄이는 법**: 트래픽이 포함된 베어메탈·전용 서버 업체 사용, 상태 압축·관심 영역(멀리 있는 사람은 덜 자주 전송), 서버 틱을 장면에 따라 낮추기.
- **호스팅 업체 주의**: Unity의 **Multiplay 서버 호스팅은 2026-03-31에 Unity 서비스로서는 끝났고**, 소프트웨어는 Rocket Science(“Multiplay by Rocket Science”)가 이어받아 운영 중(가격 미공개). Unity Matchmaker·Relay·Lobby는 영향 없음. 5단계 때 후보: AWS GameLift, Edgegap, Multiplay by Rocket Science, 직접 운영(Agones 등) — 그때 가격을 다시 비교한다.

### 5.3 진짜 위험은 서버비가 아니라 "빈 대기열"
40명 매칭 게임은 동시접속이 적으면 판이 안 열려 사람이 떠난다. 그래서 **친구 방을 기본으로, 공개 매칭은 수요 확인 뒤**, 그리고 **봇·작은 방·1인 연습**을 처음부터 설계에 넣는다.
